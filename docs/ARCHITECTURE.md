# CodeShield 比赛版设计

## 产品定位与边界

CodeShield 是离线桌面代码审计工具，解决源码中硬编码密码、Token、API Key、私钥、数据库连接串和可选个人信息的发现、解释、处置与复扫验证。比赛版围绕四项亮点：多维检测、可解释评分、前后扫描对比、全程离线与默认脱敏。

不进入比赛版的能力包括联网检测、Git 历史扫描、AI/机器学习、自动修改源码、PDF 报告、账号系统和云端协作。它们会扩大测试面，却不能强化五分钟演示的核心闭环。

## 工程结构

```text
main.py                 程序入口与无界面自检
codeshield/
  bootstrap.py          配置、数据库等运行对象的装配
  config.py             JSON 设置
  database.py           SQLite 表结构与数据访问
  comparison.py         基于指纹的扫描快照比较
  reporting.py          离线 HTML 与 JSON 报告生成
  models.py             Finding、扫描统计和规则模型
  language.py           文件类型与语言映射
  scanner.py            文件遍历、保护与读取流程
  rules.py              规则加载、候选匹配与增强协调
  context.py            硬编码、变量、注释和测试特征
  entropy.py            Shannon 信息熵
  validation.py         身份证、JWT 和数据库来源验证
  risk.py               风险因子与最终评分
  masking.py            Finding 展示值脱敏
  ui/                   页面、扫描线程和样式
rules/                  内置规则数据
tests/                  单元与集成测试
demo_project/           全部为虚构或失效的演示样本
docs/                   架构、演示和交付说明
```

模块按职责拆分，不引入 Repository、Service、Factory 等多层包装。SQLite 查询集中在 `database.py`；界面线程不直接拼 SQL。

## Finding 数据结构

项目使用 dataclass 表示一次发现：

```text
rule_id, risk_type, severity, score
file_path, line_number, language
masked_value, reason, entropy, risk_factors, context, suggestion, status
fingerprint
```

`masked_value` 用于展示；内存中的原值只在当前检测步骤短暂存在，不写数据库。`fingerprint` 由规则、相对路径、位置附近稳定特征和敏感值摘要组成，用于前后扫描匹配。

## SQLite 设计

- `scan_history`：项目、时间、耗时、文件数、风险分布和任务状态。
- `scan_results`：Finding 展示字段、状态与指纹，不保存原始 Secret。
- `custom_rules`：用户新增的正则、风险类型、基础分和启用状态。
- `whitelist`：敏感值 SHA-256、路径模式或规则 ID，以及必要备注。

设置继续使用 JSON；它是少量可读键值，不需要塞入数据库。删除一次扫描时通过外键级联删除所属结果。

## 扫描流程、持久化与线程

```text
校验目录 → 遍历候选文件 → 文件保护与安全读取 → 基础规则候选
        → 上下文与结构验证 → Shannon 熵 → 风险因子 → 0～100 评分
        → 脱敏 Finding → 稳定排序 → 返回统计与文件级错误
```

这是核心层的同步链路。Phase 5 通过构造参数向扫描器注入当前启用的自定义规则、禁用的内置规则 ID 和白名单匹配函数。白名单在风险项完成脱敏和评分之后、最终结果返回之前匹配，不修改正则，也不让扫描核心依赖 Qt 或数据库类型。

GUI 使用一个 `QThread` 承载单次扫描任务。`ScanWorker` 调用真实 `ProjectScanner`，通过信号返回进度、完成结果、取消结果或可读错误；主线程只根据这些信号更新 QWidget。取消操作设置线程安全事件，扫描器在目录枚举和文件边界主动退出，不强制终止线程。扫描结束后，主窗口先以一个事务保存历史摘要和全部脱敏结果，再把同一个 `ScanResult` 交给结果页；保存失败时内存结果仍可查看，并显示明确提示。

```text
ScanPage（主线程） → QThread / ScanWorker → ProjectScanner（纯 Python）
        ↑                    │                     │
        └── 进度/结果信号 ───┴──── ScanResult ─────┘
                              ↓
                Database（事务快照）→ ResultsPage（筛选与详情）
```

历史回看从 `scan_results` 恢复安全快照，并复用同一个 `ResultsPage`，不会重新读取已经变化或无法访问的源码。风险状态是快照上唯一允许更新的处置信息；等级、分数和风险因子保持扫描时事实。`scanner.py`、规则、评分、熵值、上下文、验证、脱敏和数据模型不导入 PySide6，因此 CLI 和测试仍可独立使用扫描核心。

## 三层检测与评分

第一层是高确定性的格式规则，如私钥头、JWT、厂商 Token、含凭证的数据库 URI。第二层识别敏感变量名与直接字符串赋值，并排除环境变量读取、函数调用和明显注释。第三层计算 Shannon 熵、长度与字符组成；高熵只提供旁证，不能独立产生严重风险。

评分按证据累加并限制在 0～100：

- 规则基础分按类型为 15～85；
- 敏感变量、直接字符串赋值各加 12；
- 达到配置长度和阈值的高熵凭证加 8，长度加 4；
- 私钥、有效 JWT、明文数据库认证等强格式加 8～10；
- 注释减 12，测试路径减 10，演示标记减 8，占位值减 18；
- 环境变量或模板变量等安全来源减 45。

严重 75～100、高风险 50～74、中风险 30～49、低风险 0～29。每项加减分写入原因列表，详情页按实际证据展示。

## 误报抑制与规则管理

`example`、`dummy`、`your_api_key`、重复字符等只降权，不直接丢弃。环境变量读取不作为硬编码；注释和测试目录降低评分；邮箱、手机号和身份证规则可整体关闭。身份证候选必须通过日期和校验位，JWT 候选必须能解码出 JSON 头部和载荷。

Phase 5 的白名单支持现有指纹、相对文件路径、目录前缀和规则 ID。命中项从普通结果中移除，同时累计 `suppressed_findings`；白名单可禁用或删除，避免不可逆隐藏。内置规则的启停状态保存在 `rule_overrides`，不修改 `builtin_rules.json`。自定义规则保存在 `custom_rules`，编译失败或缺少命名值分组时拒绝保存，单条错误不会扩散到扫描流程。

## GUI 与后续报告

左侧保留概览、项目扫描、扫描结果、扫描历史、检测规则、白名单、报告中心、设置和关于。概览展示 SQLite 累计数据和最近一次真实扫描。历史、规则和白名单采用轻量工具栏与表格；风险详情显示脱敏上下文、评分依据、修复建议和五种处置状态，不允许回显原始凭证。

项目扫描页负责目录选择、扫描配置、任务状态、进度和取消。结果页支持关键词、等级、类型和语言组合筛选，默认按严重程度和分数排序。用户选择“误报”只更新状态，只有单独点击“加入白名单”才保存指纹，防止一次误操作永久隐藏风险。

Phase 6 增加两条保持纯 Python 的数据链路：

```text
SQLite 历史快照 → previous completed 查询 → Comparison Engine → ComparisonPage
SQLite 脱敏快照 → Report Generator → 单文件 HTML / JSON
```

同一项目用规范化 `project_root` 识别，基线只取当前扫描之前最近一次 `completed` 记录。对比引擎把两次风险项建成以 fingerprint 为键的字典，使用键集合交、差运算得到 `new`、`persistent` 和 `resolved`，避免风险数较大时出现双重循环。用户处置状态不参与事实比较；白名单抑制可能表现为 resolved，因此页面和报告明确说明“已消除不等于已修复”。

`reporting.py` 不导入 Qt。HTML 对所有动态文本执行 `html.escape`，使用内嵌 CSS 和简单条形图，不包含 CDN、外部字体、脚本或网络资源；JSON 使用固定四段结构、UTF-8 中文和缩进格式。两类报告都只读取数据库中已经脱敏的内容，Private Key 仍只显示文件头与 `[MASKED]`。

对比页双击风险后回到现有 `ResultsPage` 展示完整详情，没有复制第三套详情组件。报告中心只负责历史选择、格式选择、输出目录和错误反馈。概览在原四项累计数字和最近扫描基础上，增加累计等级条形与最近五次已完成扫描列表，不引入图表依赖。

## Demo 与测试

`demo_project` 按语言放置最小样例，当前覆盖高熵与占位 Token、注释凭证、测试路径、明文和动态数据库 URI、有效结构与错误 JWT、身份证校验、私钥头及环境变量不误报。所有样本使用明确标注的虚构、失效值，私钥样例不包含任何密钥主体。

测试分为四层：算法单元测试、文件扫描集成测试、临时 SQLite 事务与恢复测试、Qt 页面/线程冒烟测试。Phase 5 还覆盖历史级联删除、状态恢复、四类白名单、自定义规则 CRUD、规则启停和原始 Secret 不落库。

## Phase 1～7

1. 基础工程：入口、主窗口、导航、配置、SQLite、稳定启动。
2. 基础扫描：遍历、文件保护、读取、规则匹配、Finding。
3. 检测增强：上下文、熵、评分、误报抑制、脱敏。
4. 扫描界面：线程、进度、取消、筛选、详情和状态。
5. 项目管理：历史、白名单、自定义规则、设置。
6. 比赛亮点：报告、前后对比、概览统计和可视化。
7. 提交准备：demo、测试、README、PyInstaller、演示和发布检查。

## 方案审查

当前设计只引入 PySide6 一个直接第三方依赖，算法、数据库和报告均使用标准库。前后对比以 Finding 指纹完成，不解析 Git；图表优先使用 QtCharts，若展示价值不足则保留数字卡片和简单表格。自定义正则必须在保存前编译验证并设置扫描边界，避免错误规则拖垮任务。扫描不跟随符号链接、不读取超限或二进制文件，单文件失败只记录路径与错误类型，不记录其内容。

界面导航完整，但功能严格按阶段标记，避免出现只有按钮没有逻辑的演示假功能。注释只保留算法取舍、安全原因和兼容细节；清楚的函数与普通数据流不写重复 Docstring 或逐行说明。
